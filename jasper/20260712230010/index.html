VLAN Trunk over Wi-Fi

导语

古早的需求,完全没时间弄,这个周末终于搞定了.

主从路由通过 WIFI 互联.主路由已经划好多个 VLAN,从路由插上网线后,下面的虚拟机也要能直接拿到 VLAN tag.

需求就是 VLAN over WIFI.从路由只做二层扩展,网关,DHCP 和防火墙仍然留在主路由.

VLAN tag 属于 Ethernet frame,普通 WIFI STA 不能直接当成 Ethernet trunk.所以先用独立 WIFI 建一条 IP underlay,再由 GREtap 封装完整的 Ethernet frame:

方案

从路由原本就是 5G STA 直接挂进 LAN,同时开 WDS.沿用这条链路最省事,但 LAN/WDS 和 GREtap trunk 一起进同一个 bridge,二层环路也就来了.

最后还是单独拆一条 WIFI backhaul.它只承载 GRE 外层流量,不进 LAN,也不开 WDS.所有业务 VLAN 都走 GREtap.

两端 underlay 使用一个独立 /30:

这里没选 VXLAN.一共就两个固定端点,GREtap 足够了.纯路由当然也能通,但 DHCP,mDNS 这些广播和组播还要额外处理,反而麻烦.

动从路由的 bridge 前,先留一个不经过 GRE 的救援 SSID,再挂一个定时回滚.不然管理 VLAN 一断,后面的配置也不用看了.

MTU

到这里 trunk 已经通了.小包 ping 稳定在 0.5-1 ms,SSH 也正常,看起来没什么问题.但是从 GRE/VLAN 打开 LuCI 慢得不对劲,最后是 1472 字节 DF ping 露了馅:

坑在封装开销.GREtap 要装下 1500 字节 Ethernet frame,underlay 还要留出 GRE 和 IP header 的空间.把 GREtap MTU 保持为 1500,WIFI backhaul 提到 1600 后,DF ping 和网页访问都恢复正常.

一开始只改了 network.bh.mtu,结果实际 WIFI netdev 还是 1500.OpenWrt 这一层显示改了不算,必须直接检查 mac80211 创建出来的设备:

config device 在重启后有效,但 WIFI reload 以后 MTU 仍可能掉回 1500.最后还是在两边加 /etc/hotplug.d/iface/95-bh-mtu:

脚本权限设为 0755,并把路径加入 /etc/sysupgrade.conf.

WIFI 重载

MTU 修好后本来以为结束了.结果从路由只要执行一次 wifi reload,underlay 很快恢复,GRE/VLAN trunk 却不再转发.bridge 和 VLAN membership 都还在,ifstatus gt 甚至显示 up: true.

这个 up: true 只能说明 netifd 觉得接口还活着.对比内核设备关系才看到问题:

状态bhsta0 ifindexgre4t-gt iflink
正常1212
wifi reload 后1412

WIFI reload 删除并重建了 bhsta0.名字没变,ifindex 已经从 12 变成 14; 原先带 tunlink 'bh' 创建的 GREtap 还指着已经消失的 ifindex 12.

还有一层坑:gre4t-gt 是 br-lan 的静态端口,bridge 一直引用着它.单独执行 ifdown gt; ifup gt 并不会真正重建内核 tunnel,手工删除 gre4t-gt 反而会让内核与 netifd 状态对不上.

修复反而很简单:gt 删除 tunlink,同时设置 nohostroute '1'.GREtap 不再记 WIFI ifindex,netifd 也不再给 peer 添加 host dependency.外层包按 /30 直连路由走当前 backhaul.
