北京联通烽火光猫不改桥接放行 IPv6 入站（转载）

发表于 2026-07-15 分类于 折腾 ， HomeLab 阅读次数： Disqus： 本文字数： 1.6k 阅读时长 ≈ 1 分钟

  • 原文: 烽火光猫不要超密不改桥接的前提下关闭 IPv6 防火墙, 作者 Libitum, 2024-10-29.

  • 设备资料: FiberHome HG6145D2.

  • 本文为转载整理, 操作思路来自原文; 背景、验证方式与安全提醒为自己的使用记录.

  • 更新

导语

北京地区想折腾运营商光猫, 现在是真的难.

超密基本拿不到. 万能的闲鱼也没有办法, 最多只是尝试改桥接, 我这边还屡次被拒. 但我的需求其实不复杂: 让家里的 IPv6 服务能够从外网访问.

DDNSv6 已经勉强能用, 地址变化可以处理. 问题在于光猫默认会拦截 IPv6 入站流量. 域名能正确解析到家里, 端口仍然一动不动.

最后搜到了 Libitum 的这篇文章. 不需要超密, 也不用改桥接, 只用普通管理页面里的端口过滤就能绕过去. 这个确实解决了大问题, 所以转载整理一份, 免得以后再找.

先说结论: 在烽火光猫的 WAN-LAN 接入控制中启用白名单, 可以让匹配的 IPv6 入站流量通过默认防火墙.

原文测试环境

原作者只在下面这组硬件与固件上验证过:

项目信息
运营商联通
厂家FiberHome / 烽火
型号HG6145D2
硬件版本WKE2.094.443
软件版本RP0302

其他型号即使页面长得一样, 规则实现也可能不同. 这里不能直接当成烽火全系列通用方案.

设置

使用普通管理员账号进入光猫后台, 找到:

然后按原文设置:

  1. 勾选 启用 IP 地址过滤.
  2. 过滤模式选择 白名单模式.
  3. 新增一条规则并启用.
  4. 协议选择 ALL.
  5. 目的端口最小值填 80, 最大值填 65535.
  6. 添加并应用规则.

如果只需要少数服务, 端口范围应当尽量收窄. 不过原作者提到, RP0302 存在一个 bug: 端口范围可能不会按填写值精确生效, 随便填写一段也可能变成全部放行. 所以不能只看后台配置判断结果, 一定要从外网扫描或连接验证.

按原作者的测试, 还有一个坑: 这套白名单同时影响 IPv4. 如果已经配置了 IPv4 端口映射或其他入站规则, 需要一并检查, 否则可能把原来的 IPv4 流量也挡掉. 这同样没有烽火的官方说明, 只确认于上面的单一测试环境.

为什么能用

原文给出的解释是: 光猫底层防火墙大概率仍然基于 iptables 或 nftables 的规则链.

IPv6 入站默认策略是 DROP. 继续加黑名单没有意义, 匹配与不匹配的流量最后都会被丢弃. 白名单则会给匹配流量增加一条放行路径, 从而绕过默认的入站拦截.

这部分是根据现象做的推测, 不是对固件规则的直接检查. 原作者的测试结果只能说明, 白名单确实改变了这台设备上的 IPv6 入站行为.

原文也试过按 IP 放行. 这样更安全, 但家庭宽带的 IPv6 前缀会变化, 光猫页面又不支持好用的前缀或后缀写法, 每次变动都要手工更新. 最后才选择按端口处理.

验证

DDNSv6 更新成功, 只说明 AAAA 记录已经指向当前 IPv6 地址, 不等于入站已经打通.

至少还要确认三层:

  • 目标设备拿到了公网 IPv6, 服务也监听在 IPv6 地址上.
  • 目标设备自己的防火墙放行了对应端口.
  • 手机断开 Wi-Fi, 通过移动网络实际连接这个域名与端口.

我这边做完之后, DDNSv6 这条路总算还能继续用. 不算优雅, 但在拿不到超密、桥接又不给改的前提下, 已经是目前能落地的方案.

安全提醒

IPv6 设备通常拥有可直接路由的公网地址. ALL + 80-65535 不是普通的“端口映射”, 而是把大量设备端口直接暴露到公网.

所以我不会把它当成一次设置完就不管的开关. 最少应该做到:

  • 只开放真正需要的服务与端口.
  • 服务本身启用强认证和 TLS.
  • 优先只暴露 VPN, 再通过 VPN 回家访问其他设备.
  • 从外网检查实际开放端口, 尤其注意前面提到的固件 bug.
  • 不再使用时立即删除规则.

这个方案最大的价值不是“关闭整个 IPv6 防火墙”, 而是在运营商把正常管理路径堵得差不多以后, 还留了一条不需要超密的路.
